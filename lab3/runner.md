# Подключение машины деплоя

Для деплоя используется отдельный self-hosted runner с меткой `lab3-deploy`.
Сборка, тесты и Trivy выполняются на GitHub-hosted runner. Локальная машина
получает только задачу деплоя после успешной публикации.

## Регистрация

Владелец репозитория должен открыть Settings → Actions → Runners → New self-hosted runner
и выбрать Linux x64. Если страница возвращает 404, у текущего аккаунта нет нужного доступа.
В этом случае регистрацию нужно согласовать с владельцем репозитория.

Команды скачивания и проверки контрольной суммы берем со страницы GitHub.
Каталог установки создаем вне репозитория, например `~/actions-runner-lab3`.
В команду `./config.sh` добавляем:

```text
--name lab3-local --labels lab3-deploy
```

Временный registration token вводим локально. Он не должен попадать в репозиторий,
отчет, переписку или скриншоты. Настройки runner и его рабочую папку также
не добавляем в Git.

После настройки запускаем `./run.sh` и оставляем терминал открытым. Runner должен
показать `Listening for Jobs`, а в GitHub - статус Idle. Пользователь runner
должен иметь доступ к Docker без интерактивного sudo, а также команды curl,
openssl и flock. Версия Docker Compose должна поддерживать `up --wait`.

## Конфигурация деплоя

Пайплайн берет `images.env` из артефакта текущего прогона и использует digest
обоих образов. Для скачивания закрытых пакетов применяется `GITHUB_TOKEN`
с правом `packages: read`. Авторизация Docker находится во временном каталоге runner.

Первый запуск создает `~/.local/share/cloudtech-lab3/.env` со случайным паролем БД
и правами доступа 600. Этот файл сохраняется между релизами и не попадает в Git.
Не удаляйте его при сохраненном томе PostgreSQL: пароль должен совпадать с тем,
который использовался при создании базы.

Приложение будет доступно по адресу `http://127.0.0.1:8083`.
Данные хранятся в именованном томе Compose-проекта `lab3`. Скрипт деплоя не удаляет том.
Конфигурации релизов и ссылки на образы сохраняются в каталоге `releases/` рядом с `.env`.

Задача деплоя принимает только push в ветку `lab3`, зависит от успешной задачи
`build` и не запускается для pull request. Деплои выполняются последовательно.
